By the end of this page you will know every `vessel serve` option, where it can come from, and which order wins when the same option is set in more than one place.

## Precedence

For every option: **flag**, then a `VESSEL_*` environment variable, then the config file, then the built-in default. Dashes in a flag name become underscores in its environment variable — `--jwt-ttl` is `VESSEL_JWT_TTL`.

The config file defaults to `$XDG_CONFIG_HOME/vessel/vessel.yaml` (or `~/.config/vessel/vessel.yaml`), or an explicit path via `--config`. It is entirely optional — a missing file is not an error, only a malformed one is.

## Validation

`vessel serve` (via `cmd.NewConfig`) rejects a few combinations outright, with a plain `exit code 1` error rather than silently coercing them:

- `--port` must be between 1 and 65535.
- `--log-level` must be one of `debug`, `info`, `warn`, `error`.
- `--jwt-ttl` must parse as a positive Go duration (`24h`, `30m`, …).
- `--addr` must not be empty.

`--base-path` defaults to `/` when empty; it is otherwise used verbatim as the prefix the router and the embedded UI both mount under, so it must match whatever your reverse proxy strips or forwards.

## Docker host resolution

`--docker-host` (or `VESSEL_DOCKER_HOST`, or the config file) is used verbatim when given. Otherwise Vessel falls back, in order, to the plain `DOCKER_HOST` environment variable (the same one the `docker` CLI honours), then the first of these that exists as a real Unix socket:

1. `~/.docker/run/docker.sock` — current Docker Desktop (macOS and Linux)
2. `/var/run/docker.sock` — classic Linux daemon, and older Docker Desktop's compatibility symlink
3. `$XDG_RUNTIME_DIR/docker.sock` — rootless Docker on Linux

and finally to the hardcoded default `unix:///var/run/docker.sock`. `vessel doctor` and the startup banner both report which of these it picked and why.
