## `vessel`

A single-binary web UI for the Docker containers on one host

Vessel is one binary. Drop it on a machine that runs Docker, start it,
open a browser, and see and control every container, image, volume and
network on that host.

Running vessel with no subcommand is a shortcut for "vessel serve".

| Flag | Default | Description |
| --- | --- | --- |
| `--addr` | `127.0.0.1` | Bind address |
| `--allow-exec` | `true` | Set false to remove the console entirely |
| `--auth` | `false` | Require login. Implied when any user exists |
| `--base-path` | `/` | Serve under a sub-path behind a proxy |
| `--db` | `*(none)*` | SQLite file. Omitted means in-memory store |
| `--docker-host` | `*(none)*` | Docker Engine API host (auto-detected if omitted) |
| `--i-know-what-im-doing` | `false` | Override the loopback-or-auth bind guard |
| `--jwt-ttl` | `24h` | Access-token lifetime |
| `--log-level` | `info` | debug\|info\|warn\|error |
| `--open` | `false` | Open a browser on start |
| `--port` | `7373` | Bind port |
| `--read-only` | `false` | Serve GETs only; every mutating route returns 403 |
