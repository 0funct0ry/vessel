Every container on the host, on one page.

Vessel is a single binary with the web UI inside it. Copy it to the machine, run it, open a browser. No agent, no database server, no control plane, nothing to keep running afterwards.

What you can do with it

Everything here is in v0.1.0. Nothing here is behind a licence key, a signup, or a "contact us".

Run the lifecycle

Start, stop, restart, pause, kill, rename and remove containers. Select several and act on all of them, with a per-container result when one fails.

Read the logs

Stream with follow, tail, since and a substring filter. stderr is separated properly — Vessel demultiplexes the engine stream instead of guessing.

Watch the numbers

Live CPU, memory against limit, network and block I/O per container, computed the way docker stats computes them.

Open a shell

An interactive terminal inside a running container, in the browser. Every session is logged. Turn it off entirely with --allow-exec=false.

Manage images

Browse, inspect layers, pull with per-layer progress, tag, remove, prune with a reclaim figure before you commit.

Volumes and networks

Create, inspect and remove — with the back-reference that matters: which containers use this volume, and at which IP on this network.

Dispatch webhooks

Turn Docker events into signed HTTP POSTs. Filters, retries with backoff, a delivery log you can read, and one-click replay.

Gate it with logins

Optional JWT auth with bcrypt credentials in SQLite and three roles: viewer, operator, admin. Or run --read-only and hand it to anyone.

Or keep no state at all

Omit --db and Vessel keeps everything in memory. Nothing is written to the host. Vessel says so at startup.

Vessel is for one box you can SSH into: a VPS, a home server, a CI runner, a dev machine. It stops being the right tool the moment you have three of them.

The Docker socket is root

Anything that can reach Vessel's API can control the host. Every default follows from that, and one of them will stop you the first time you try it.

Vessel will not bind a public interface without authentication

Run vessel serve --addr 0.0.0.0 without --auth and it exits instead of starting:

refusing to bind 0.0.0.0:7373 without --auth
Vessel proxies the Docker socket, which is equivalent to root on this host.
Either bind loopback and use an SSH tunnel:
  ssh -L 7373:127.0.0.1:7373 user@host
or create a user and enable auth:
  vessel user add admin --role admin --db vessel.db
  vessel serve --db vessel.db --auth --addr 0.0.0.0

Loopback by default

Binds 127.0.0.1:7373. The intended remote workflow is an SSH tunnel, which needs no new credentials at all.

Read-only mode

--read-only rejects every mutating request at the middleware, not in the UI. The recommended way to let someone else debug.

Env values are masked

Container environment usually holds credentials. Vessel masks values and logs a line when one is revealed.

Console is optional

--allow-exec=false removes the route, not just the button. Sessions that do happen are logged with user, container and command.

Webhooks are admin-only

An endpoint that POSTs anywhere is an SSRF primitive. Only admins can create one, redirects are not followed, bodies are HMAC-signed.

Login is throttled

Exponential per-user backoff, constant-time comparison, and the same error for a wrong password and an unknown user.

Running in about thirty seconds

  1. Get the binary. The install script, a GitHub release, go install, or Homebrew. Linux and macOS, amd64 and arm64.
  2. Run it. No flags needed. Vessel finds /var/run/docker.sock and prints the URL it is listening on.
  3. Decide about state. Add --db when you want users and webhooks to survive a restart. Leave it off and nothing touches the disk.
  4. Reach it from your laptop. An SSH tunnel, or --auth with a user you create.
# local, no state, no login
$ vessel serve

# persistent, with logins, behind a tunnel
$ vessel user add anirban --role admin \
    --db /var/lib/vessel/vessel.db
$ vessel serve --db /var/lib/vessel/vessel.db --auth

# check the host before anything else
$ vessel doctor
socket   /var/run/docker.sock  ok
engine   27.3.1 (API v1.43)    ok
uid 1000 in group docker       ok
